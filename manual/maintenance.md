# Maintenance and owner concerns

[Manual contents](README.md)

## Find an issue

The Maintenance page shows issue cards with property, status, priority and reported time. Select a card to review it. Filter by status, find a property by name, or choose a category or priority; results update automatically. **More filters** contains reporter, evidence, expense, follow-up and date filters. **Clear filters** returns to the full issue list. **Issues** and **Owner concerns** tabs appear above the results; Maintenance remains the sidebar destination.

Issue details show the property name, description, status, priority and reporter first. Use the main buttons to edit, start, resolve, cancel or reopen an issue. The **More issue actions** dropdown contains scheduling, provider, cost, follow-up and work-entry commands. Forms group related fields and show the issue context with a return link at the top; recovery controls appear when needed. Empty related sections stay collapsed; photos, conversations and change history remain available below. Reported times use your browser's local time zone.

## Report and triage a repair

1. Open **Maintenance → Report maintenance issue**.
2. Select property and optional rental unit, enter what happened, category, priority and report time.
3. Identify the reporter and role explicitly. Self-reported operator context differs from a client owner or tenant. Historical attribution may require a reason/confirmation.
4. Review existing issues to avoid duplicates, then save.
5. Use **Edit issue** to change details or correct reporter attribution. A reporter change requires a correction reason. **Save changes** saves both together; if validation fails, neither change is saved. The report date, property and issue status stay unchanged.
6. Start the issue when work begins. Use waiting/follow-up to track external dependencies without hiding urgency.

For immediate safety concerns, take the appropriate real-world action; entering an urgent record does not contact emergency services or a provider.

## Quotes and provider assignment

Before assigning work, open the provider and choose **Manage official IDs**. Record at least one license, driver's license, passport or other supported ID: issuing country, last four characters and optional state/expiration. You can optionally save a full number for any Provider ID when needed for reference or warranty records; **Show ID number** reveals it on the provider page, and **Hide ID number** conceals it again. A record containing only the last four characters cannot reveal the full number. No document scans are stored here, and recording an ID does not verify identity, licensing, qualifications or warranty eligibility. Check those independently.

Full numbers are hidden by default and excluded from directory summaries and general activity. They remain in contextual history, saved unfinished forms, command receipts and backups—even after editing or removing the current entry. Save full numbers only when needed and protect your workspace and backups. Provider profiles and quotes may be saved without an ID, but new assignments and reassignments require one. Existing assignments and their original retry results remain available.

1. Open the issue and **Record provider quote** for each candidate. Enter provider, scope, amount, received/valid dates and applicable proposed start/finish dates/terms.
2. Compare the retained quotes. A quote is not spending.
3. **Assign provider** using the selected quote, or use the explicit direct-assignment option with the required reason.
4. Review avoided-provider overrides and reassignment reasons before confirming.
5. Withdraw a quote or end an assignment through its explicit action; retain history.

A provider assignment does not send a booking or prove work is complete. Contact the provider outside the app and record the contact/appointment.

## Appointments, follow-up and work history

Schedule an appointment with actual start/end and purpose. Review displayed local zone/UTC context. Reschedule explicitly when plans change. **Finish appointment** records the offered completed/cancelled outcome; it does not resolve the issue.

Use **Create issue follow-up** for a linked Task, then set who/what is awaited and a follow-up instant. Existing deadlines and source urgency remain independent. If a provider does not respond, record the additional conversation and reschedule the follow-up rather than erasing the previous history.

**Record work journal entry** for each relevant visit/work outcome: what was done, when, by whom, assignment and evidence. Distinguish reported completion from what you physically verified. Add files through the issue's evidence controls.

## Costs and paid expenses

**Record cost context** retains an estimate or work-reported amount; void an erroneous context entry explicitly. Record actual paid spending in Money, then **Link paid expense** to the issue. Review the property and rental-unit match. Archive the association if it is incorrect; that does not void the Finance expense. Quotes, costs and paid expenses must not be counted as three payments.

## Resolve, cancel or reopen

1. Review physical outcome, remaining work, provider assignment, appointments, journal and evidence.
2. Use **Resolve maintenance issue** only for the actual reviewed outcome, with required dates/reasons.
3. Close or update remaining Tasks/appointments independently where appropriate.
4. Use Cancel, Reopen or Return issue to open for the matching lifecycle change; record the explanation required by the form.

Completing a Task/appointment or ending assignment does not resolve an issue. Recording the provider's message is not physical verification.

## Owner concerns

Use **Owners → Owner concerns** or the **Owner concerns** tab in Maintenance (`/maintenance?tab=concerns`) for a client owner's operational rental/lease/tenant/vacancy concern. Each Owner overview shows their concerns with **View all concerns** and **Record concern** actions; recording from an Owner preselects that owner. Record the Property, context, raised date and evidence; retain historical owner context only with required review.

The primary filters are **Owner → Property → Suite → Concern type**. Search owners and properties by name; **Suite** appears only for an office property. Selecting **Lease** or **Tenant** as the concern type shows a **Lease period** dropdown with inclusive end dates, rental names and statuses. Lease choices use the selected property and, when chosen, the owner's current and former property relationships. **More lease periods** loads another bounded page; a page without matches may still have more periods. Changing the property, owner or suite clears dependent lease/tenant filters. A separate Tenant name search and status, priority and date filters are also available. Results update automatically; **Clear filters** removes all selections.

Use Edit, Start, Reopen, Resolve or Dismiss to reflect the actual concern lifecycle. Add conversations and **Create concern follow-up** as needed. Concern resolution does not change a Lease, occupancy or money, and linked Task completion does not resolve the concern.

Legal/eviction case administration and HOA notice/shared-repair coordination have separate planned interfaces; do not treat a general repair or attorney provider category as those complete workflows.
