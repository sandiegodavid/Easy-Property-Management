# Troubleshooting

[Manual contents](README.md)

## Opening the application

| Symptom | Action |
| --- | --- |
| Browser cannot connect | Check the server terminal is running. Use the exact loopback address/port from the launcher, on the same computer. Restart with the configured command if stopped. |
| `web_build_unavailable` | Ask the installer to build/package and stage the compiled frontend for the chosen runtime. An editable Python installation alone does not provide it. |
| Workspace missing | Check the external folder is mounted and the absolute config path is correct. Do not initialize an empty replacement. |
| Workspace Busy | Look for another server using it. Shut that instance down normally; do not delete lock files or run competing writers. |
| Invalid/unsupported workspace | Preserve records, stop writes and contact the installer. Check the approved release/config and restore a validated compatible archive if needed. |
| Foreign-origin/Host rejection | Open the application using its local origin directly. Do not use a remote/proxy URL or enable permissive development origins for production. |
| A destination disappeared | Check More and Settings navigation. Capability-unavailable routes explain their limitation; hidden is different from unavailable. |

## Forms, uncertain saves and conflicts

| Message/situation | Safe response |
| --- | --- |
| Unfinished form saved | Input is recoverable; official submission still requires its action. |
| Outcome unknown | **Check original result**. If instructed, **Retry original attempt** with the same retained request; do not open a new replacement transaction. |
| Source changed/revision conflict | Review the latest owning record, preserve/recheck edits and explicitly confirm current source before resubmission. |
| Missing child after removal | Recover the original operation from the saved attempt; a later missing-child read does not prove the removal failed. |
| File reselection required | Select the original bytes. Name/size/hash must match; a different file needs a new properly reviewed upload flow. |
| Payment saved, upload failed | Inspect the payment/receipt first, then retry only the evidence attachment. |
| Invalid field/oversized content | Keep input, correct the indicated field or reduce the identified content/file size. Do not split financial records merely to bypass validation. |
| Saved-form capacity reached | Review completed/resolvable entries through Unfinished forms. Do not discard unresolved command outcomes to make space. |

## Home and lists

Slow reads should leave navigation and typing available. Review each section's capture/check time; a successful live attention check does not refresh another section's money/coverage timestamp. Use Retry or Refresh Home after transient failure. Known stale/failed attention means issues may be missing; inspect source workflows directly.

Use the **New items need attention** update action to show new ordering; your current editor may remain visible separately. View all uses full server counts. If a collection changed/expired, Restart with the retained filters instead of combining old and new pages. Verify Property, horizon, period, status and archived filters before concluding a record is missing.

## Money or status looks wrong

Open the source detail and history. Distinguish agreement from actual receipt, expected rent from allocation, scheduled check from deposited check, owner claim from verified receipt, and cost estimate from paid expense. Check dates/time zones and correction/void lineage. Money by owner is not a calculated payout balance. Task/appointment completion never substitutes for issue resolution or move-out.

## Evidence unavailable or backup failed

Inspect the retained metadata/storage state. Do not manually change managed paths. For remote evidence, ask the installer to check configured bucket/version access. A full Intake read may fail when its required audit cannot be recorded; do not bypass that read protection.

For backups, verify the destination is mounted/supported, sufficient storage is available, passphrase is correct and required remote file versions are accessible. Use the command's failure reason, preserve the original workspace/archive and contact support rather than disabling validation.

## Contact support

Provide the application/release identity if known, screen/action, time, selected scope, safe error/correlation identifier and whether the outcome is uncertain. Explain whether a payment or other record may already have committed. Do not send secrets, raw financial identifiers, private source messages or the workspace itself without an explicit appropriate support arrangement.
