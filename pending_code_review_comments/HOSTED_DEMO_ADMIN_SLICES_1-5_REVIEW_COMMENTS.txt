SPECIFICATION — Fresh synthetic workspace provisioning

1. [P1] Coordinate reserved workspace initialization with the demo seeder.
Status: resolved (2026-10-29)
File: application/apps/server/app/modules/hosted_admin/infrastructure/prepare_workspace.py:17-29
Related: application/demo/seed.py:545-548

prepare() initializes the reserved workspace before calling the existing demo seed prepare(). The initializer populates the destination but does not create the seed journal. The seeder then rejects that destination with RuntimeError: "Destination is populated without a demo journal; choose an empty folder." This occurs for every fresh default synthetic setup, so provisioning cannot complete the workspace step or reach provider verification and invitation.

Recommendation: coordinate fresh initialization and journal creation through an explicit seed entry point that preserves the reserved workspace UUID and safely resumes partial seeds. Retain the rejection of unrelated populated destinations. Add a focused test invoking the actual preparation helper and installed seed script, including retry, rather than mocking the runuser result.

Evidence: reproduced with prepare() and application/demo/seed.py in a fresh temporary directory, without mocking either initializer. The focused setup, Linux setup, provisioning and pre-enrollment suites passed (34 tests), demonstrating that the current simulated effects do not cover this integration failure.

Resolution: The hosted helper now delegates synthetic initialization to the installed seeder with an explicit reserved workspace UUID. The seeder persists its scenario metadata and journal before initialization, checks reserved identity and configuration consistency on retry, and retains the populated-without-journal rejection. Empty-template initialization remains direct. Five integration regressions exercise the real helper, a copied installed seed script, workspace initialization and domain API writes; they cover interrupted initialization, a lost committed-write response, completed retry identity stability, foreign populated destinations and empty-template retries.

backup() replaces the child environment with PATH, LANG and PYTHONDONTWRITEBYTECODE, omitting TMPDIR. The source helper calls create_hosted_backup(), which unconditionally builds the hosted storage budget. Its validator requires both TMPDIR and Python's effective temporary directory to equal this instance's volume/tmp. The independently launched helper therefore fails backup validation even for an otherwise valid volume. Pre-enrollment recovery cannot produce its required proof, leaving onboarding at readiness. The running service's systemd Environment does not apply to this separate runuser subprocess.

Include the server-owned instance volume/tmp in the child environment and verify it reaches the source process before tempfile initializes. Add a regression at this subprocess/source-helper boundary; the current pre-enrollment tests substitute platform.backup() and miss the required environment.

SPECIFICATION — Broker responsiveness and authority fencing

4. [P1] Keep status and urgent authority fences available during slow commands.
Status: still open
File: /Users/dcai/Desktop/My Apps/Easy-Property-Management/application/apps/server/app/modules/hosted_admin/infrastructure/broker.py:146-154
Related: /Users/dcai/Desktop/My Apps/Easy-Property-Management/application/apps/server/app/modules/hosted_admin/infrastructure/authority.py:386-387
Requirement: /Users/dcai/Desktop/My Apps/Easy-Property-Management/docs/hosting/design/HOSTED_DEMO_ADMIN_DESIGN.md:263-265

The broker uses synchronous UnixStreamServer and executes source commands/private operation-run inside its sole request handler. While an external source call runs, all other RPCs queue behind it, including status, urgent disable and administrator revocation. This defeats the priority-fence requirement: the revocation request cannot record its generation change until the in-flight grant has already finished. Frontend asynchronous fetching does not remove this server-side serialization.

A transport-level reproduction used the real Broker.serve, AuthorityStore, PrivateOperations and OperationEngine with a controlled slow source effect. A concurrently submitted revoke_identity remained pending with administrator.enabled=1. Releasing the effect allowed the approval operation to reach succeeded; only afterward did revocation execute. Installation ownership checks and the external effect were simulated; no host resources were changed.

Use bounded concurrent handling or a separate admission/control lane so slow effects do not occupy the only RPC accept loop. Preserve database serialization, worker locking and current fencing checks. Add a Unix-socket regression that holds a source effect open while status and revocation/disable are serviced, then verifies containment before a fenced grant can be reported successful.
