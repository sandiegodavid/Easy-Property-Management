1. [P2] Exclude only SQLite's literal reserved prefix from structural validation
Status: resolved (2026-11-11)
File: application/apps/server/app/platform/hosted_schema.py:79

The LIKE pattern 'sqlite_%' treats '_' as a single-character wildcard, so user-defined tables, indexes and triggers named sqliteX... are excluded from the actual schema comparison. Reproduced by initializing an Admin store, executing CREATE TABLE sqliteXunexpected(value TEXT), then calling initialize_store() again: it returns already_initialized instead of rejecting the altered store. The same filter lets create_schema() treat a connection containing such objects as empty. This violates H02.2's exact structural validation and partial-store rejection. Use a literal-prefix comparison such as GLOB 'sqlite_*' and add regression coverage for unexpected tables and triggers with these names, including nonempty-store creation rejection.

Resolution: structural comparison now uses NOT GLOB 'sqlite_*', excluding only
the literal reserved prefix. Added both-store regression tests for unexpected
sqliteX tables, indexes and triggers, byte-preserving reinit rejection, and
nonempty caller-owned creation rejection.
