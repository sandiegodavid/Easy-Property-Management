UPGRADE / ROLLBACK

3. [P1] resolved (2026-11-01) — Rollback rejects the inventory state produced by interrupted acceptance.
File: application/apps/server/app/modules/hosted_admin/infrastructure/upgrade_deployment.py:60-68
Related: application/apps/server/app/modules/hosted_admin/infrastructure/upgrade_deployment.py:366; application/apps/server/app/modules/hosted_admin/infrastructure/upgrade_deployment.py:399-401.
Acceptance reconciles inventory to revision+1 and the target release before source resume can fail, for example due to concurrent disablement. Rollback changes the expected release to the original, so its first stop inspection rejects this already-reconciled target state with admin_upgrade_inventory_changed. The operator remains paused and the offered rollback cannot recover. Permit the pinned reconciled-target state during rollback and reconcile it back through a new expected-revision transition; the existing early return for an already-reconciled reservation must not skip this update. A focused real-fixture reproduction confirmed the rejection.

Resolution: Rollback accepts the pinned reconciled target. If forward acceptance already reconciled inventory, rollback creates its own expected-revision reservation and reconciliation back to the original release; it preserves the forward receipt and concurrent disablement. Tests cover lost replies after finish/reconcile, idempotent acceptance, unrelated-revision rejection, and isolation of another operator.
