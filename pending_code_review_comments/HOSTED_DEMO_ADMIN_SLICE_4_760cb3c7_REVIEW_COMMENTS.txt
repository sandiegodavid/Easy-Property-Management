SPECIFICATION — Browser observation availability

1. [P2] Bound pending reads so a stalled connection cannot preserve an available status indefinitely.
Status: still open
File: application/apps/web/src/admin/reads.ts:92-96
Related: application/apps/web/src/admin/reads.ts:118-132; application/apps/web/src/admin/main.tsx:49-58

The fetch has no deadline, and the next poll is scheduled only after the fetch and JSON body finish. If a refresh stalls while the page remains visible, no retry or failure state is scheduled. Previously returned observations continue to display Available even after their freshness window has elapsed; an initial stalled request remains Loading indefinitely. This violates the design's latency/failure requirement to show retained information as stale during connection loss.

Add a bounded deadline covering both the response and body read. Treat deadline expiration as a failed read, retain prior data with a stale indication, and schedule bounded backoff. Distinguish timeout cancellation from deliberate visibility/unmount cancellation, since the existing aborted-signal early return would otherwise suppress retries. Test an unresolved initial request and an unresolved refresh after success, then verify recovery when subsequent requests succeed.
