Specification — durable effect reconciliation

1. [P2] Allow verified containment to reconcile obsolete unknown effects
Status: resolved (2026-11-12)
File: application/apps/server/app/modules/host_agent/infrastructure/inventory.py:268-272
Related: application/apps/server/app/modules/host_agent/infrastructure/inventory.py:648-666

An uncertain start permanently blocks subsequent starts and repairs after a successful explicit stop. Reproduced with the owning SQLite inventory and existing test fixtures: prepare successfully; return unknown for a start; apply a new stop successfully; retry the original start; submit a fresh start at the current binding revision. The stop advances the binding revision, so can_inspect() prevents reconciliation of the original receipt. That receipt remains unknown, and the unresolved-receipt check rejects every fresh start/repair (and retirement). Verified containment therefore leaves the operator unavailable with no supported recovery path. Add an authenticated reconciliation/supersession path that retains original intent, records the verified containment of obsolete effects and permits newly admitted work once uncertainty is resolved. Never replay an obsolete start. Cover unknown start -> verified stop -> explicit successful restart, including a newer access fence.

Specification — guarded runtime supervision

2. [P2] Use current fenced authority when supervising a restarted container
Status: resolved (2026-11-12)

Related: application/apps/server/app/modules/host_agent/infrastructure/stop_registry.py:182-190
Related: application/apps/server/app/modules/host_agent/infrastructure/gateway.py:196

StopRegistry retains the first start command when the same container is started again, and Supervisor passes that historical command into current runtime verification. Gateway.verify() requires its access_epoch to match current ingress authority. Reproduced with the real inventory, HostAgent, StopRegistry, NativeEffects, RuntimeAuthority, Gateway and Supervisor using synthetic physical adapters: initialize and start at epoch 1; stop successfully; apply held ingress at epoch 2; successfully execute a newly admitted start at epoch 2. The retained stop target still contains epoch 1, so the next Supervisor.poll() stops the running container. This repeats for subsequent restarts of the same container. Preserve immutable stop-only identity, but resolve current supervision authority through the owning inventory or a separately protected current supervision projection. Add a stop -> newer held fence -> restart -> guardian poll regression that verifies the container remains running while stale actual authority still causes containment.
