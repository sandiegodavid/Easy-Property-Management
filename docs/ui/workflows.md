# Operator workflows

Each workflow uses the owning module's commands, revisions, confirmation rules and immutable original receipts. Browser forms use generated contracts and registered Operator recovery. Consult the linked module for domain policy and the linked source for exact current forms/routes; these guides replace backlog slice narratives as the developer entry point.

## Create and edit completion

Property create/edit uses a labeled native State selector with all 50 US states and Washington, D.C. Full names are displayed; new choices submit two-letter codes. Existing full-name values display the matching choice without rewriting recovered input or original attempt identities. The server accepts state names and codes for address time-zone lookup, while retaining the same ambiguous/conflicting-evidence rejection. `property-states.spec.ts` covers keyboard selection, draft recovery, create and edit; Portfolio's state-time-zone tests cover aliases, multi-zone evidence and persistence validation.

Standalone record create/edit workflows replace their editor with `SavedCommand`/`SavedItem`: a contextual success heading, readable saved business data, and an explicit **Back to [item]** button. Property creation/editing no longer redirect automatically. Return navigation targets the item (or its owning record for a child) without adding the completed form as a new parent. Embedded Task quick-add, AI connection creation and AI draft edits use the same presentation inside their enclosing content, without page navigation. AI controls allow an explicit new connection or return to draft review.

Completion appears only after the existing command/recovery contract acknowledges success. Details come from the immutable owning receipt, not a fresh mutable item read. If that read fails, keep the success confirmation and offer a read-only retry; never resubmit the mutation. Unknown outcomes and validation/conflict failures keep the original form and recovery actions. Lifecycle commands use the same saved-data presentation with a contextual completion heading. Filter forms, immediate settings toggles and write-only credential controls retain their existing behavior.

Forms collect missing-field feedback with operator labels and move focus to the error summary after a failed submission. Routine chrome omits source revisions, attempt identities and API field/unit boilerplate. Information review uses the same bottom action row: **Record review** and **Save unfinished form**. Calendar dates display as `Oct 1, 2026` without changing their source day; system activity uses browser-local time; monetary displays use grouped `USD 1,950.00` while request values retain their original numeric units.

Every recoverable form shows saving, saved or failed feedback beside its action row. **Unfinished form saved** includes the saved time; the draft-save button reads **Saved** until another edit needs saving. Date/time filters use browser-local controls and send zoned instants. Settings distinguishes the automatically saved Home refresh interval from appearance and navigation choices saved with **Save preferences**.

Scheduling forms use the shared time-zone selector; task editing and reminders use the same editable date/time picker as task creation. Conversations have no time-zone input: the server stamps new conversations in UTC and derives their time-zone context from the linked property in the same transaction (UTC for unlinked records). Edits and corrections preserve the original stamp and zone. Reminder time zones are display choices only (the reminder command stores an instant). Work-journal event and recorded times both use browser-local formatting, with the source zone named when different. Owner reports show the entered **Received on** date before the automatic **Recorded** stamp and render one amount even when both decimal and minor-unit representations are returned.

New scheduling, deadline, follow-up and reminder inputs default to the related property's time zone, including tasks linked through a rental unit, lease or maintenance issue. With no single property context they default to the browser's zone. Existing records, recovered drafts and explicit operator selections retain their zones; selecting another property only changes a default that has not been chosen or saved. Property lookup failures block scheduling instead of silently substituting the browser's zone. These defaults do not change existing instants or mutate saved input. `property-time-zones.spec.ts` proves cross-zone defaults, related-record resolution, retained choices and unavailable property handling.

Display schedules in their saved scheduling zone (the property default unless explicitly overridden): appointments, task deadlines and follow-ups use this zone in details, directories and saved results. Reminder detail uses the related property's zone because reminders retain only an instant. Property-context task projections use the property's zone when the projection supplies no scheduling zone. Without a source/property zone, use browser time. Home and its combined summaries use browser time for cross-property comparison and include the actual source-local time when different, not only the source zone name. Created, recorded, updated and audit times remain browser-local; calendar dates never shift. No persisted instant, sorting, due-state calculation or idempotency identity changes.

Focused display validation: `time-display.spec.ts` covers Portland, Austin and Eastern schedules in Pacific and Tokyo browsers, winter/summer offsets, Home's paired times, saved results, system activity, missing appointment ends and unchanged all-day dates. `property-time-zones.spec.ts` covers the real appointment/task/reminder routes and retained explicit overrides. Existing `work.spec.ts` and `context-reads.spec.ts` cover directory and contextual projections.

Waiting and rescheduling wire `followUpAt`/`followUpTimezone` to the shared zoned picker: local input becomes an offset-bearing instant, and zone changes preserve that instant. Saved commands pass their resolved property display zone through every nested saved-data section. Zone-less reminder responses use that fallback, never the Task's deadline zone; recorded/system times still use browser time. Recovered committed confirmations wait for the property lookup before displaying scheduled details and report lookup failures without resubmitting. `timezone-review.spec.ts` proves cross-zone submission/rescheduling, daylight-saving invalid input, lost-response reconciliation with one reminder write, recovered confirmation and matching Task detail. `time-display.spec.ts` also covers nested reminders with a conflicting parent deadline zone; no persistence, schema or backup format changes are involved.

Pickers collect minutes, not seconds, and use the same canonical IANA zone names as timestamp displays. Existing timestamps retain their precision until edited. Invalid local clock text stays inside the picker, blocks submission and never replaces the last valid instant in autosaved input. Task creation selects a related record by name through bounded metadata search, not by entering internal identifiers. Conversation details omit duplicate instants already shown in the header and collapse repeated history timestamps.

New maintenance issues, owner concerns, conversations and owner rent reports use the owning service's UTC clock. Their browser forms omit **Reported at**, **Raised at** and **Occurred at**; owner reports still collect the payment's **Received on** date. Display these server stamps as **Recorded**, not as the time an event happened. Edits preserve the original recorded time, as do conversation corrections; a replacement owner report receives its own recorded time. Generated browser contracts also omit these fields when recovering saved input. Application/API integrations may still supply an explicit historical instant. Missing times remain `null` in canonical command identities and are resolved only for persistence, so retries recover the original timestamp rather than creating a new request identity.

### Record rent receipt

An expectation's **Record payment** action starts with that period selected and its outstanding balance in both the payment and allocation fields. **Received on** defaults to the property's current local date. These are initial defaults only: refreshes and recovery never overwrite the operator's edits. Payment-method suggestions remain editable; method descriptions and masked references are optional Additional details.

Amounts are entered in USD dollars, accepting `2600`, `2,600` and `2600.50`; blur adds grouping and two decimal places without moving the typing cursor. Conversion uses exact integer cents, not floating-point multiplication. USD is fixed rather than an editable currency field. Open periods are a checkbox list with their balances and editable allocations. More periods load explicitly in bounded pages; **Allocate remaining…** appears only when a displayed period has enough unallocated capacity.

Draft recovery accepts bounded incomplete dollar text and mismatched totals. The totals explain the remainder neutrally; completeness and financial rules block submission, not editing or saving an unfinished form. Failed saves and cross-tab conflicts keep entered allocations visible. Strict command admission, duplicate checks, revision checks and atomic allocation writes remain unchanged.

The saved screen shows the received amount, date, method and per-period paid/remaining result. Period outcomes are computed in one set-based query inside the receipt transaction and retained in its immutable command response, so later payments or voids cannot rewrite that confirmation. No domain entities, tables or allocation rules change. Exits are **Back to rent** and **Record another payment**, which starts a fresh form against the current ledger.

## Unfinished forms and submission recovery

All registered record forms preserve incomplete input through autosave. **Save and close** acknowledges persistence before navigating to Unfinished forms; **Discard…** confirms that only saved input is removed. The existing **Save unfinished form** control permits saving in place. Explicit native validation is not applied to these draft-only buttons. Native required/format validation and schema checks run on official submission, followed by source-owned preflight checks during preparation. Invalid input remains editable and receives focused error feedback.

The recovery list groups unresolved submissions above editable forms, with bounded name/title-only recognition labels. It never fetches full payloads per row. Completed submissions leave the queue. Resuming a hosted form claims available editing access automatically; another editor is never displaced without confirmed takeover. Lease loss invalidates the local edit claim while retaining input.

Unknown submissions show a status panel above the protected input, with **Check submission**, **Discard…**, **Fix and continue**, **View submitted information**, and an explicit **Retry same submission**. Checking never dispatches the domain command. The original receipt opens the saved confirmation; missing receipts alone do not prove failure. Returning to editing requires the server to close the original transactional request durably. Discard checks success first, then uses that closure before discarding. External-effect workflows explain why closure is unavailable. Files/credentials retain their reselection and secrecy rules; official domain drafts retain their own lifecycle.

Property forms offer an optional explicit IANA time-zone choice for addresses outside the bundled lookup. The override is included in canonical command identities, retained form schemas, owning receipts and audit input. It changes scheduling context, not address verification. Ordinary address-derived behavior is unchanged when no override is supplied.

Validation matrix: `unfinished-forms.spec.ts` covers incomplete save/close/resume/discard, unsupported addresses, manual zones, final rejection, never-delivered request closure and successful lost responses. Inventory recovery tests cover same-key closure retry, delayed/changed requests, committed-result refusal, audit rollback, schema validation and encrypted portability. Task terminal-command SELECT budgets remain constant with 0 versus 100 reminders. Hosted tests cover automatic available claims, explicit takeover, retained input and lost responses across session/lease expiry.
