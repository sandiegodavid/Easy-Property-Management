# Operator workflows

Each workflow uses the owning module's commands, revisions, confirmation rules and immutable original receipts. Browser forms use generated contracts and registered Operator recovery. Consult the linked module for domain policy and the linked source for exact current forms/routes; these guides replace backlog slice narratives as the developer entry point.

## Create and edit completion

Standalone record create/edit workflows replace their editor with `SavedCommand`/`SavedItem`: a contextual success heading, readable saved business data, and an explicit **Back to [item]** button. Property creation/editing no longer redirect automatically. Return navigation targets the item (or its owning record for a child) without adding the completed form as a new parent. Embedded Task quick-add, AI connection creation and AI draft edits use the same presentation inside their enclosing content, without page navigation. AI controls allow an explicit new connection or return to draft review.

Completion appears only after the existing command/recovery contract acknowledges success. Details come from the immutable owning receipt, not a fresh mutable item read. If that read fails, keep the success confirmation and offer a read-only retry; never resubmit the mutation. Unknown outcomes and validation/conflict failures keep the original form and recovery actions. Lifecycle commands use the same saved-data presentation with a contextual completion heading. Filter forms, immediate settings toggles and write-only credential controls retain their existing behavior.

Forms collect missing-field feedback with operator labels and move focus to the error summary after a failed submission. Routine chrome omits source revisions, attempt identities and API field/unit boilerplate. Information review uses the same bottom action row: **Record review** and **Save unfinished form**. Calendar dates display as `Oct 1, 2026` without changing their source day; instants use browser-local time; monetary displays use grouped `USD 1,950.00` while request values retain their original numeric units.

Every recoverable form shows saving, saved or failed feedback beside its action row. **Unfinished form saved** includes the saved time; the draft-save button reads **Saved** until another edit needs saving. Date/time filters use browser-local controls and send zoned instants. Settings distinguishes the automatically saved Home refresh interval from appearance and navigation choices saved with **Save preferences**.

Scheduling forms use the shared time-zone selector; task editing and reminders use the same editable date/time picker as task creation. Conversations have no time-zone input: the server stamps new conversations in UTC and derives their time-zone context from the linked property in the same transaction (UTC for unlinked records). Edits and corrections preserve the original stamp and zone. Reminder time zones are display choices only (the reminder command stores an instant). Work-journal event and recorded times both use browser-local formatting, with the source zone named when different. Owner reports show the entered **Received on** date before the automatic **Recorded** stamp and render one amount even when both decimal and minor-unit representations are returned.

Pickers collect minutes, not seconds, and use the same canonical IANA zone names as timestamp displays. Existing timestamps retain their precision until edited. Invalid local clock text stays inside the picker, blocks submission and never replaces the last valid instant in autosaved input. Task creation selects a related record by name through bounded metadata search, not by entering internal identifiers. Conversation details omit duplicate instants already shown in the header and collapse repeated history timestamps.

New maintenance issues, owner concerns, conversations and owner rent reports use the owning service's UTC clock. Their browser forms omit **Reported at**, **Raised at** and **Occurred at**; owner reports still collect the payment's **Received on** date. Display these server stamps as **Recorded**, not as the time an event happened. Edits preserve the original recorded time, as do conversation corrections; a replacement owner report receives its own recorded time. Generated browser contracts also omit these fields when recovering saved input. Application/API integrations may still supply an explicit historical instant. Missing times remain `null` in canonical command identities and are resolved only for persistence, so retries recover the original timestamp rather than creating a new request identity.

Presentation-only changes do not alter domain writes, receipt formats, lifecycle rules, schemas or backup formats; the server-time defaults above change command admission without changing storage formats. List filtering stays in SQL before pagination/counting, and added name lookups use the bounded batch-name port rather than one query per row.

Presentation omits operation/record UUIDs, revisions, fingerprints and raw JSON. Instants use browser-local time; date-only values remain unchanged and minor-unit amounts are formatted as money. Official IDs use the shared masked/reveal presentation. Existing original-result APIs, persistence and backup contracts are unchanged. Money details select business fields by record and child type. Relationships and correction chains use named links instead of UUID facts; optional interest calculations show percentages and labelled days separately. Primary lifecycle actions are visible buttons on the relevant record, not a collapsed Actions group. Secondary destructive actions and history may remain disclosed.

### Record rent receipt

An expectation's **Record payment** action starts with that period selected and its outstanding balance in both the payment and allocation fields. **Received on** defaults to the property's current local date. These are initial defaults only: refreshes and recovery never overwrite the operator's edits. Payment-method suggestions remain editable; method descriptions and masked references are optional Additional details.

Amounts are entered in USD dollars, accepting `2600`, `2,600` and `2600.50`; blur adds grouping and two decimal places without moving the typing cursor. Conversion uses exact integer cents, not floating-point multiplication. USD is fixed rather than an editable currency field. Open periods are a checkbox list with their balances and editable allocations. More periods load explicitly in bounded pages; **Allocate remaining…** appears only when a displayed period has enough unallocated capacity.

Draft recovery accepts bounded incomplete dollar text and mismatched totals. The totals explain the remainder neutrally; completeness and financial rules block submission, not editing or saving an unfinished form. Failed saves and cross-tab conflicts keep entered allocations visible. Strict command admission, duplicate checks, revision checks and atomic allocation writes remain unchanged.

The saved screen shows the received amount, date, method and per-period paid/remaining result. Period outcomes are computed in one set-based query inside the receipt transaction and retained in its immutable command response, so later payments or voids cannot rewrite that confirmation. No domain entities, tables or allocation rules change. Exits are **Back to rent** and **Record another payment**, which starts a fresh form against the current ledger.

## Home foundation and deferred work

[Shared attention/calendar components](../../application/packages/ui/src/attention.tsx) provide source-supplied reasons, totals, timestamps, all-day dates and explicit timed zones through independent disclosures. Live Task deadlines/waiting directories consume them. [Home](../../application/apps/web/src/shared/home.tsx) delivers bounded source-backed attention, agenda, information review, money and inventory; [DASH-001](../archive/designs/DASH-001_DESIGN_COMPLETED_2026-10-14.md) records the accepted live composition.

The installation currently has no registered production model adapters/actions/approval handlers; Settings and generic review infrastructure do not establish production generation/approval. [functional intake/review backlogs](../active/DATA-002_DESIGN.md) retains issue-proposal approval, assistant setup, legal/HOA and spreadsheet work. Owner statements/disbursements/fees retain their separate backlogs.
