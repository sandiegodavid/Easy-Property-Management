GOAL AND NON-GOALS

Reduce redundant HTTP surface and genuinely unreachable supporting code while
preserving operator workflows, source-owned ports, original-result recovery,
audit history, bounded reads, and portable workspace validation.

Do not change the database baseline, drop stored receipts, migrate workspaces,
add compatibility aliases, expose previously gated UI controls, or implement
missing Settings features as part of this cleanup. Internal application APIs
are not unused merely because their equivalent HTTP route has no SPA caller.
Use disposable test workspaces; never test cleanup against operator data.

SLICE 4: RECEIPT LOOKUP CONSOLIDATION, BY OWNING BOUNDARY

Use the inventory's 17 alternate lookup routes as candidates, not a directive
to impose one global URL convention. Keep lookup-by-key wherever it is needed
to recover a committed command whose response and operation ID were lost.
Keep lookup-by-operation-ID wherever saved results, contextual navigation or
documented consumers use it. Both can be legitimate in the same module.

Recommended bounded order:
4a. Parties, Tenants, Providers/categories and Expense categories.
4b. Intake, Files, Inspections and Owner concerns.
4c. Portfolio inventory/status and Leasing coordinated operations.
4d. AI command/external operations and Operator preferences/form operations.

For each batch:
- Trace application/apps/web/src/workflows/workflow-result.ts, command.tsx,
  ai-governance.tsx, shared recovery code and bootstrap result-reader adapters.
  A UI using one lookup does not prove that another lookup is unnecessary for
  an outcome-unknown path.
- Record retained namespaces, input identities, response wrappers, original
  snapshot semantics, error mappings and readiness checks before changing HTTP.
- Remove an alias only when all required recovery paths remain reachable. Keep
  application recovery functions used by OPS or other owning workflows.
- Do not replace original receipts with current detail, add automatic retries,
  or consolidate independent Lease/Space or Property/status revisions.

Focused verification for every affected command family:
- Same key/payload returns the original result after later record changes.
- Changed payload under the same key conflicts; stale revision stays typed.
- Simulate commit followed by lost response, reload/restart, and reconcile via
  the original key without knowing the operation ID. One mutation, revision
  change and required audit chain; no repeated publication/provider call.
- Existing rollback/failure-injection coverage still proves no partial result.
- Unknown receipts return the documented absent-result response, not current
  state or a rerun. Recovery GETs perform no business writes or external calls.
- Focused encrypted restore proves original receipts and their result references
  remain recoverable with stable IDs/audit correlations after reopening.

Exit: fewer aliases only where justified; no reduction in recovery guarantees.

1. Regenerate OpenAPI, schema types and workflow dispatch using the existing

6. Update the inventory dispositions and report removed/retained/deferred routes,

VERIFICATION MATRIX

Happy paths:
  Surviving directories, names/contact selection, Money/Lease/Property context,
  downloads, appointment cancellation and original-result detail still work.

Invalid combinations:
  Invalid IDs/filters/limits, missing records, archived eligibility, busy/not-ready
  workspaces, membership violations and stale cursors retain typed behavior.

Idempotency and retry:
  Original key recovers unknown outcomes across reload/restart and later edits;
  payload mismatch conflicts; one effect/receipt/audit chain. No fallback to a
  new key or reconstruction from mutable current records.

Transaction rollback:
  Required audit/result failure leaves no partial business effects; coordinated
  Lease/Portfolio and File publication cleanup remain atomic/accounted for.
  Reuse relevant existing fault-injection tests and add cases only for changed
  recovery or transaction wiring.

Persistence/schema:
  Current-schema and retained-data validation accept representative receipts and
  audit history before/after cleanup; no schema migration/table/trigger changes.
  HTTP removals do not remove retained-data validators or operation records.

Backup/restore:
  Focused encrypted round trip compares stable IDs, original response snapshots,
  correlations and evidence references for affected receipt families; credentials
  remain excluded and new runtime epochs invalidate old view continuations.
  Route-only read removals may reuse shared existing portability coverage; record
  why no new portable format test is needed, rather than claiming it was rerun.

Query budget/N+1:
  Replacement reads remain bounded and set-based; matching totals use complete
  predicates in the same snapshot. Check query upper bounds, not an incidental
  exact query decomposition. No all-pages or per-row-detail browser workaround.

Routing/contracts/security:
  Only approved method-paths/operation IDs disappear. Surviving methods on shared
  paths remain functional; parameter routes do not absorb removed static paths.
  Local Host/Origin policy, readiness guards and no-workspace export remain intact.

Browser integration:
  Named navigation and saved-result links resolve; lost-response recovery, filters,
  paging and relevant reload behavior remain intact. No raw IDs/locators/secrets
  become visible because a replacement returns a different response shape.

DEFINITION OF DONE

Every inventory candidate has an evidence-backed disposition. Approved deletions
and only those deletions are reflected in runtime routes, generated contracts,
tests and current documentation. Focused gates pass with recorded results; any
blocked check is explicitly incomplete. Recovery, audit, portability, security,
bounded reads and operator-visible capabilities are preserved. Operational
integration gaps remain separately listed, not silently removed or expanded.
