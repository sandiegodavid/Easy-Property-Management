12. [P1] Unauthenticated GET /auth/start on both Admin and Operator origins allows trivial 15-minute global sign-in lockout DoS
File: application/apps/server/app/modules/hosted_access/infrastructure/admin_sessions.py:143-172
Related: application/apps/server/app/modules/hosted_access/api/admin_identity.py:107-112; application/apps/server/app/modules/hosted_access/api/destination_identity.py:90-155; application/apps/server/app/modules/hosted_access/infrastructure/destination_identity.py:136-144

Both Admin GET /auth/start (global cap 128 in main.login_attempts) and Operator GET /auth/start (global cap LIVE_SESSION_CAP=32 in main.source_login_attempts) are unauthenticated, unthrottled GET endpoints that insert durable 15-minute pending rows and fail closed with ProviderDenied (401) for all callers once the global count is reached. Any unauthenticated remote caller (or cross-site subresource request) can send 32 or 128 GET requests in under a second to lock out all legitimate Admin or Operator sign-ins, renewals and email-link continuations indefinitely. Rate-limit GET /auth/start per client network, and either use a stateless signed challenge cookie for pre-auth browser binding or evict the oldest unredeemed anonymous pending attempt (keeping authenticated renewals/continuations in a separate budget). Also prune expired admin_login attempts so login_attempts does not grow unbounded.

13. [P1] Zero clock-skew tolerance breaks legitimate Firebase sign-ins under normal NTP drift
File: application/apps/server/app/modules/hosted_access/infrastructure/firebase_tokens.py:218-223
Related: application/apps/server/app/modules/hosted_access/infrastructure/firebase_rest.py:341-342; application/apps/server/app/modules/hosted_access/application/admin_admission.py:35; application/apps/server/app/modules/hosted_access/infrastructure/admin_sessions.py:206

Token and cookie timestamp checks enforce strict zero-skew bounds: authenticated <= issued <= now < expires and nbf <= now (firebase_tokens.py:220-222), proof.expires_at <= int(clock() * 1000) + duration * 1000 (firebase_rest.py:341), and authenticated_at + 999 >= row["created_at"] (admin_sessions.py:206). Because Firebase mints tokens using Google's server clock, even a 1-second NTP lag on the host causes issued <= now and the createSessionCookie expiry check to reject 100% of fresh Admin and Operator sign-ins with ProviderDenied (401); a >1s lead rejects fresh logins at admin_sessions.py:206. 14. [P1] CertificateCache._certificates rejects the entire Google key bundle if any single certificate is outside [not_valid_before, not_valid_after)
File: application/apps/server/app/modules/hosted_access/infrastructure/firebase_tokens.py:105-127

_certificates() iterates over all kid -> pem entries returned by Google's X.509 certificate endpoints and raises ValueError() (mapped to ProviderUnavailable / 503) if any single entry has now < not_valid_before_utc or now >= not_valid_after_utc.
