1. [P1] The shared policy adapter breaks expense and owner-rent-report file operations.

The new _Targets adapter exposes active_link_count(connection, entity_type, entity_id), but ExpenseFileLinkValidator calls active_link_count(connection, entity_id). It also exposes exists(connection, entity_type, entity_id), while OwnerRentReportFileLinkValidator calls exists(connection, entity_id). Expense uploads through the composed application service therefore raise TypeError, and any workspace containing owner-rent-report evidence fails retained-data validation during startup, backup, or restore. Use the owning modules' existing adapters, or define separate explicitly typed fact ports instead of one adapter with incompatible call shapes.

2. [P1] Full verification misses orphan content in configured stores that have no retained rows.

Verification builds by_provider only from database candidates. If a process published the first local or S3 object and stopped before metadata commit, that provider can have an orphan while having no retained rows. The provider is then never reconciled and the response reports zero orphans with complete=true. Iterate every configured store and reconcile it with an empty retained-location set when necessary.

3. [P1] Verification still returns complete=true when reconciliation finds storage problems.

The complete flag describes only whether the loop or cursor stream ended. Local or S3 orphaned, missing, or unverifiable results do not change it. This creates the complete-looking result prohibited by the design and cannot safely clear workspace-integrity attention. A completed scan and a clean result need distinct semantics, or complete must be false whenever unresolved storage problems remain.

4. [P1] Cleanup failures still do not preserve exact cleanup identity or create the required operational attention.

_S3Lease does not retain publication_id. Batch commit and rollback collect bare exceptions and then identify the first or last lease, which may not be the lease whose cleanup failed. Direct S3 publication verification followed by rollback failure is also converted to a generic FileError before FileService receives a lease. The code still records no system-actor file_publication_cleanup/cleanup_incomplete event, exposes no workspace-integrity attention, and cannot clear that attention after a clean full verification. Track each failure with its exact lease/publication identity, propagate PublicationCleanupIncomplete, and persist the privacy-safe attention lifecycle required by the design.

5. [P1] Retained-data validation still omits active-link limits.

validate_file_data delegates to each policy's validate_retained method, but expense, deposit, general maintenance, and owner-report retained validators check target and purpose only. Their active-link limits are enforced only on new writes. A restored workspace containing more than the permitted number of active links can therefore pass FILE-001 validation, apart from the separate partial check for maintenance work-journal evidence. Add retained aggregate/count validation for every registered link type.

6. [P2] S3 reconciliation is not resumable through the application boundary.

The S3 adapter limits each provider request to 1,000 versions, but the verification service consumes every page in one HTTP request. The endpoint accepts no continuation cursor and returns none, so the operator cannot stop and resume a large scan; an outage or cancellation restarts it from the beginning. Return the opaque continuation after one bounded page and let Settings or the maintenance workflow continue explicitly.

7. [P2] Archived work-journal evidence remains in normal evidence lists.

The general maintenance projections were changed to active_links_for_entities, but work_journal_files still uses the history-inclusive links_for_entities method. Both issue-journal and provider-history responses consequently include archived attachments in each row's files list. Use active_links_for_entities for these normal projections and reserve the unfiltered read for contextual history.

8. [P2] The new policy registry violates the documented module-composition boundary.

files/application/policy_registry.py imports SQLAlchemy, a concrete file reader, owning-domain validators, and owning-domain table names. ARCHITECTURE.md requires cross-module protocols to be composed at bootstrap and prohibits a module from importing another module's SQLAlchemy model or concrete repository to enforce cross-module rules. Keep policy ownership in the domain modules, put connection-bound fact adapters behind their existing protocols, and compose those adapters at bootstrap and schema-validation composition roots.

9. [P2] The FileLinkValidator generic-upload capability remains an implicit, permissive contract.

FileLinkValidator requires allows_generic_upload, but production validators other than the inspection validator omit it. FileService hides incomplete implementations through getattr(..., True), so adding a new validator silently enables the public generic upload route. Declare the decision on every validator and access it directly so registry construction or type checking fails closed.
