## How to use this backlog

Each item has a stable identifier, phase, delivery sequence, outcome, and ordered dependencies. New ideas should be added here before being surfaced in the product.

The sequence column gives the recommended delivery order. Optional sub-sequences such as 26a are stable insertion labels; execute only after all listed prerequisites, not at their table position. The dependency column contains only hard prerequisites and lists them from left to right in the preferred implementation order; it does not imply that each prerequisite depends on the one before it. `None` marks a true starting point.

UI development is explicitly deferred until `UI-001`, immediately before `DASH-001`. Before then, implementation is limited to backend domain logic, persistence, migrations, APIs, CLI/setup capabilities, tests, and documentation; do not build React screens, shared web packages, or other operator-interface surfaces.

Features with required operator workflows can have verified backend/API scope while remaining in progress. `UI-001` delivers the confirmed [operator design](UI-001_DESIGN.md), including the existing domain UI acceptance criteria and newly enumerated backend prerequisites. Design approval does not mark implementation complete. `DASH-001` then supplies Home aggregation; later feature slices add capabilities only after their sources exist.

Superseded rows preserve historical sequence IDs and are not active implementation dependencies. The active intake order is AI-GOV-001 → INGEST-001 → INGEST-002 → MCP-001; all pending INGEST-001 review deficiencies are readiness blockers that must be resolved and verified before INGEST-002 starts. Optional matching in ISSUE-AI-002 consumes source/governance contracts and must not gate base review. Agent access can be unavailable while manual entry remains usable. ISSUE-AI-001 is reactivated for optional built-in extraction over retained evidence; it is not a prerequisite for reviewing an externally generated proposal. Production model adapters are capability-gated within AI-GOV-001; no vendor is mandatory. AI-LOCAL-001 is an optional pilot and does not gate UI-001 or manual workflows. UI-001 now depends on MCP-001 for working assistant setup; unavailable adapters still render honest setup states.

The status column shows delivery progress. `✅ Done` means the item is implemented and verified; `🟡 In progress` means implementation is underway but acceptance criteria remain; a blank status means it has not yet been completed. Completed dependencies appear as green badges in the dependency column. `⏭️ Superseded by X` means the item was retired in favor of item X on 2026-09-23 (native inbound email ingestion moved to assistant/manual intake); its sequence number is retained for history.

The MVP is a single-user application that runs locally. It has no application authentication, cloud account, remote portal, or shared workspace. The product owner runs setup scripts for each MVP user; self-service installation and update flows are out of scope. Connections to read-only Google Sheets use provider authorization stored on the local device; they do not create application users. Inbound email arrives through an authorized connected assistant (MCP-001) or manual import; the app holds no mail or SMS-provider credentials. Voice notes are recorded or imported locally and do not require an external account.

## Experimental — Universal Reader, parallel track

This optional experiment is independent of DATA-001, DATA-002, and DATA-003. It neither replaces their scopes nor adds prerequisites to them or to any existing backlog. `E1`–`E6` are delivery labels within this parallel track, not insertions into the existing product sequence. The experiment owns its snapshot, candidate, review, and commit contracts; it may reuse existing file, governance, connection, and domain capabilities through application protocols. Its interfaces must not call or require DATA-owned services, tables, schemas, or UI flows. See [research and attachment comparison](UNIVERSAL_READER_RESEARCH.md).

Early experiments use synthetic/consented fixtures and CLI/API tooling. Web UI work remains deferred until UI-001; the optional pilot UI is a separate later item. LLM/Jev evaluation does not promise either vendor, and local inference requires the separately qualified AI-LOCAL-001 path when selected. Google Sheets and AI assistance are optional branches, not prerequisites for the local manual path. Production enablement requires measured value, verified review/commit safety, and explicit operator authorization; successful extraction alone does not authorize import.
